# AI 产品创新与设计协同平台（暂定）

> 技术产品介绍与需求调研稿｜V0.1｜2026-10-14  
> 正文可用于向潜在用户介绍产品概念；附录供访谈人员和产品团队内部使用。产品名称与最终交付范围待调研确定。

## 一、给受访者的产品介绍

### 30 秒介绍

我们正在探索一款面向**物理产品创新**的 AI 工作台。它希望把市场线索、产品构思、三维设计、设计检查和视觉表达组织到同一个项目过程里，让个人创作者更容易把想法变成可讨论的方案，让企业团队更容易在产品、研发和营销之间传递设计信息。

目前原型由两组能力构成：**Cogad** 侧重调研、多智能体协作与 Rhino/Grasshopper 三维建模；**AI 视觉工作台**侧重家具产品图、空间场景、海报和视频内容。两组能力正在向统一产品收敛，跨工作台的自动数据流转仍是需要验证的产品方向。

### 这个产品面向谁

| 用户 | 常见任务 | 希望得到的结果 |
| --- | --- | --- |
| 个人创作者、独立设计师、创客和小型设计团队 | 从灵感或参考资料出发，探索外观、建立初步模型、制作展示图 | 一个能讨论、修改和展示的产品方案；更少的工具切换与重复整理 |
| 家具、家居及其他物理产品企业的企划和研发团队 | 调研机会、形成概念、建立三维方案、复核尺寸并迭代 | 可追溯的设计依据、模型和检查记录；更顺畅的部门协作 |
| 品牌、电商和营销团队 | 把已确认的产品方案转为场景图、产品图和宣传素材 | 可选的视觉方案、成套海报和视频素材 |

当前视觉能力主要在**家具与家居**场景中开发；对其他产品品类的适用性是本次调研要验证的重点。

### 可探索的四段工作

1. **发现机会**：收集公开网页、技术资料、代码与市场信号，整理目标人群、使用场景、现有方案和可能的产品缺口。对于需要较长时间的采集任务，后台任务可持续执行并返回状态和报告。
2. **形成设计**：让统筹智能体分派调研、工程、几何建模和质量检查任务。设计人员可在 Rhino 8 中创建和修改几何体，使用 Grasshopper 探索参数化形态，并查看尺寸、包围盒和视口截图。
3. **表达产品**：输入产品图、线稿、材质和场景参考，生成产品效果图、局部修改图、空间摄影镜头和多种候选方案。AI 识别出的尺寸、材质或结构信息可作设计参考，关键事实仍由人确认。
4. **准备传播素材**：在创意画布中规划画面与文案，组合产品图和场景图，排版并导出九屏电商海报；视频生成功能以外部模型任务方式提供。

用户可以从其中任一环节开始。把四段工作自动连接成一个统一项目，是拟议整体产品的重要方向；现阶段需要分别验证每段工作对用户是否有价值，以及用户真正需要哪些交接点。

### 用户可能拿到的结果

| 结果 | 适合的使用方式 | 当前边界 |
| --- | --- | --- |
| 机会与调研报告、设计说明 | 讨论目标用户、痛点和设计方向 | 信息来源与结论需要人工核查；机会质量尚无统一指标 |
| Rhino 场景中的三维形体、参数与测量结果 | 探索外形、尺寸和空间关系 | 对外 CAD 文件格式、制造公差和后续工艺交付需按项目确认 |
| 几何检查结论与视口截图 | 比较方案并定位明显尺寸或造型问题 | 不能替代正式工程评审 |
| 产品图、空间图和局部特写 | 设计评审、方案沟通及营销选图 | 属于生成式视觉内容，产品结构和规格须以确认数据为准 |
| 单张海报、九屏 JPEG 套图及 ZIP 包 | 电商详情页和品牌内容制作 | 当前主要模板针对家具家居，其他品类与画幅需验证 |
| 视频方案与生成任务结果 | 展示产品使用情境或功能概念 | 生成是否成功、时长、画质与成本取决于可用模型渠道 |

### 技术实现概览

| 层次 | 目前采用或探索的方式 | 对用户意味着什么 |
| --- | --- | --- |
| 项目与交互 | Web 项目工作台、对话式任务入口、文件和任务面板；原生桌面端在建设中 | 围绕一个产品项目组织讨论、文件和执行过程 |
| 智能体协作 | 统筹智能体与调研、工程、几何、QA、机会雷达等专业智能体 | 复杂任务可以分工，建模结果可交由独立角色检查 |
| 工具与执行 | Rhino 8、Grasshopper、工作区网关、浏览器和 GitHub 检索、桌面与 RPA 工具、异步任务网关 | AI 可以调用具体工具执行工作，并记录任务状态 |
| 视觉生产 | 图像模型网关、产品与场景生成、创意画布、海报排版和视频任务 | 从设计资料生成可评审的视觉方案与营销素材 |

据 Cogad 的技术说明，建模操作由本地网关传给 Rhino 宿主执行；长任务进入后台队列并保留状态；项目工作区按目录和权限约束文件操作。视觉工作台由 Web 前端、服务端生成网关、项目资产存储与外部模型服务组成。两套工作台的统一身份、产品数据和资产版本规则仍需设计与验证。

三维建模需要 Rhino 8 及相应运行环境。视觉生成依赖模型服务，具体质量、成本和速度会随任务和模型变化。平台尚未承诺生产级 CAD 公差、自动 BOM、完整制造工艺文件或跨系统无缝流转。

### 一个可能的使用例子

一家家具团队想探索新的单人功能椅。企划人员先整理用户对坐姿、空间占用和材质的反馈；设计师据此调整外形参数并在 Rhino 中检查尺寸；团队选定方案后生成室内效果图、局部特写与营销海报。这个例子用于说明产品方向，其中“建模数据自动传递给视觉工作台”的体验仍需设计和验证。

### 我们希望听到的真实反馈

我们想了解你目前如何完成这些工作、哪些步骤最耗时、哪些结果必须由人确认，以及你愿意在哪个环节尝试 AI。请按实际项目经历评价；即使你只需要其中一小段能力，也能帮助我们确定产品首先应该解决的问题。

## 三、内部使用：需求调研提纲

### 访谈目标

本轮调研不预设必须做一款覆盖所有环节的产品，重点回答四个问题：

1. 哪一类用户最常遇到高频、高成本的问题？
2. 用户最先愿意为哪一种**具体输出**付费或投入试点？
3. 三维工程能力与视觉营销能力之间，哪些数据确实需要贯通？
4. 质量、权限、部署、成本或学习门槛中，哪个因素会阻止真实使用？

### 所有受访者都问

1. 请回忆最近一次从想法到展示或交付的产品项目。你们从哪里开始，最后交付了什么？
2. 哪一步花费最多时间？最近一次大约用了多少人、多少天、多少次返工？
3. 当前使用哪些工具？在哪些工具之间需要重复录入、截图、导出或重新解释产品信息？
4. 哪些判断可以接受 AI 给建议？哪些内容必须由设计师、工程师或负责人签字确认？
5. 如果先解决一个步骤，你最希望拿到什么文件或结果？怎样判断它已经可用？
6. 你会在什么情况下放弃使用这样的工具？请结合过去使用类似工具的经历说明。

访谈时先问最近一次真实项目，再展示上文的产品概念，避免能力列表影响受访者对问题轻重的判断。展示后可追问：“这里哪一段与你的实际工作最相关？哪一段你不会使用？为什么？”

### 个人创作者与小团队加问

- 你是否使用 Rhino、Grasshopper 或其他 CAD？如果需要安装 Rhino 8，是否会改变你的使用意愿？
- 你更需要可编辑的三维形体、快速效果图、作品集素材，还是能拿去打样的文件？
- 你每月大约完成多少个产品概念？目前每个概念在工具、外包或生成服务上花费多少？
- 你倾向按次、按月还是按项目付费？哪些功能需要先体验后才愿意付费？

### 企业团队加问

- 谁提出需求、谁操作工具、谁审核设计、谁批准采购？这些是否属于同一个部门？
- 你们的产品主数据存在哪里？SKU、尺寸、材料、版本和审批记录由谁维护？
- 哪些格式必须进入后续研发或营销流程？例如 Rhino 原生模型、工程图、结构清单、图片、视频或版式源文件。
- 是否要求内网或私有部署、权限隔离、审计记录、模型供应商限制和数据保留期限？
- 如果做一次试点，你愿意提供什么样的真实产品和验收标准？试点成功后采购如何决策？

### 访谈记录建议

每位受访者至少记录：角色与所在行业、最近一次真实任务、频率、当前耗时与成本、最想要的输出、最低可接受质量、必须由人确认的事实、现有系统与文件格式、采购或付费方式、试点阻碍。把“受访者实际做过的事”和“对概念的态度”分别记录。

## 四、内部使用：产品收敛判断

调研结束后，优先比较三个可单独成立的切入点：

| 切入点 | 首个可交付结果 | 需要验证的关键假设 |
| --- | --- | --- |
| 个人创作者的概念表达 | 从参考资料到可评审的产品概念图和展示素材 | 用户是否愿意持续使用；是否真的需要 Rhino 深度建模 |
| 企业研发的工程协作 | 可修改的参数化模型、测量与 QA 记录 | 企业是否能提供可信产品数据；输出是否进入现有设计流程 |
| 家具品牌的视觉生产 | 产品场景镜头、成套海报和视频方案 | 产品一致性、人工审核成本与素材交付效率是否达到业务要求 |

若验证跨系统整合有价值，下一阶段应先统一**项目 ID、产品/SKU 主数据、工程确认值、CAD 版本、视觉资产版本和任务状态**，再设计 Rhino 结果到视觉工作台的资产交接。产品规格需要标明来源和确认人；AI 从图片推断的尺寸只能作为待核实建议。
